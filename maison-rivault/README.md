# Maison Rivault website (v2)

> To put this on Shopify, use the theme in `../shopify-theme` (upload `../shopify-theme.zip`). This folder is the static prototype used for design review.

A static, mobile-first prototype. Shopify could not be connected from this build session, so this is the fallback in the brief: plain HTML, CSS and a little JavaScript, generated by one Python script from two data files. It is built to be ported to a Shopify theme later; every product, price, tier, bundle, availability mode and date lives in `data/products.json` and `site.config.json`.

## Run it

```
py build.py                      # writes ./site (production, per SITE_MODE) and ./preview (full store)
py -m http.server -d site 8000       # what visitors will see: the waitlist page
py -m http.server -d preview 8001    # the full store, for reviewing the design
py tools/check_placeholders.py   # lists everything still to replace
```

On Mac or Linux use `python3` instead of `py`. Open http://localhost:8000 and http://localhost:8001. Run each server in its own window.

Deploy `site/` only. `preview/` is the full store with prices hidden, marked noindex and labelled "Preview build, not live". It exists so you can review the design before launch.

## The two switches (`site.config.json`)

| Flag | Values | Effect |
| --- | --- | --- |
| `SITE_MODE` | `"waitlist"` (default) or `"live"` | `waitlist` builds a landing page (logo, one line, email field, "Doors open mid-December.") plus Privacy and Terms. `live` builds the full store into `site/`. |
| `SHOW_PRICES` | `false` (default) or `true` | `false` shows "Price at launch" everywhere and disables Add to cart, even if a price is set. `true` shows a price only for items whose `price` is not `null`. |

`py build.py --mode live` forces the full store into `site/` without editing the config.

## Where things live

| What | Where |
| --- | --- |
| Products, tiers, availability mode per product, bundles, colors, photos, fiber, fit, care | `data/products.json` |
| Domain, Instagram, contact email, shipping windows, preorder policy, holiday cutoff, returns, email provider, analytics, Shopify domain | `site.config.json` |
| Design tokens (colors, type, spacing) | CSS variables at the top of `src/assets/css/main.css` |
| Page copy and layout | `build.py`, one function per page |
| Cart, signup, consent, filters | `src/assets/js/site.js` |
| Logos | `src/assets/img/logo/` (`lockup.svg` and `monogram.svg` are cropped from the master) |

## Rules built into the site

- **No invented facts.** Anything not yet confirmed shows as an orange `[confirm: ...]` marker, and `tools/check_placeholders.py` counts them. Origin, "handmade", "limited edition" and named yarns are never stated. The only date is "Est. 2026".
- **Prices:** every price is `null` with `price_status: "tbd"`. One real price per item, no was-prices, no timers, no stock banners. A bundle saving appears only when the bundle and every piece have prices, and only if the bundle really is cheaper.
- **Bundles** have their own pages (`bundles/<slug>.html`) with size selectors, availability and what is included. Every product page also lists the bundles that include that piece, with the saving once prices exist, so a bundle can be offered at the point of sale.
- **Availability:** each product is `made_to_order`, `in_stock` or `preorder`. The page states the mode and the ship window from `shipping.*` in the config. Every mode is currently marked unconfirmed.
- **Holiday:** until `holiday.cutoff_date` is set and `cutoff_confirmed` is `true`, product and shipping pages say "We cannot yet promise delivery before December 25."
- **Photos:** every image slot is a flat cream placeholder with a caption. Swap one by setting `"src"` on that image in `products.json` and putting the file in `src/assets/img/photos/`.
- **Email signup** posts to Klaviyo or a generic JSON endpoint. If neither is set, the form says signup is not connected; it never shows a thank-you unless the request succeeded. The Klaviyo call follows their client subscription API but is untested against a live account.
- **Analytics** (GA4, Meta Pixel) load only after a visitor accepts the cookie banner. The default is decline.
- **Cart and checkout:** the cart lives in the browser. Checkout builds a Shopify cart link from `commerce.shopify_domain` and each item's `shopify_variant_ids`, and stays disabled until those exist. Bundles need their own Shopify variants.

## Decisions I made that you should check

- Bundle contents: The Layering Bundle and The Cold Morning Set are assumed to use Signature pieces. The Weekend Layers shows "crewneck + one more piece" with the second piece unset.
- The Full Rotation is the five Signature pieces.
- Essentials launches with a quarter-zip and a knit polo, marked "likely, unconfirmed".
- "Coming next" lists a cardigan, trousers and footwear. The overshirt is not shown anywhere, since the brief only says it is not in Drop 001.
- Color per style is a placeholder assignment.
- Tier names are provisional and flagged.
- The launch target of Dec 14, 2026 is stored but not shown. The site only says "mid-December".

See `PLACEHOLDERS.md` for the full checklist. The logos were traced from an AI-generated image; have a designer redraw clean vectors before any print or embroidery.
